## 分类规则

### 源站类型

- `official_meta`：竞赛目录、分析报告或官方元数据入口
- `official_portal`：政府、教育或公共机构入口
- `official_platform`：由主办机构或企业运营的正式比赛平台
- `official_competition`：单个长期赛事官网
- `official_network`：系列赛或联盟活动入口
- `platform`：承载第三方赛事的专业平台
- `aggregator_host`：既聚合又提供报名/承载能力
- `aggregator`：仅用于发现赛事线索

### 基础来源等级

- `O1`：可作为事实来源的一手官方站
- `O2`：专业托管平台，单场仍需核验主办方
- `A2/A3`：聚合与发现源
- `U`：待核验

### 发现状态

- `known_active`：当前已知仍在运营，但不代表所有字段完成审计
- `needs_recheck`：需重新确认当届入口、域名或页面结构
- `candidate`：仅作为候选线索，不能进入抓取生产环境

## 重要结论

1. **国内不能简单使用“教育部认可”标签。**  
   中国高等教育学会发布的竞赛分析报告与目录是重要参考，但产品应准确注明发布主体，并结合具体高校自己的认定办法。

2. **国际没有统一权威目录。**  
   必须按主办方、历史、评审、结果、参赛范围和机构认可逐项核验。

3. **聚合源与事实源分离。**  
   赛氪、Unstop、StudentCompetitions、Devpost 等适合发现候选；最终事实必须尽量回溯赛事官方页。

4. **先建来源库，再写采集器。**  
   每个源站先记录页面结构、登录要求、API/RSS/Sitemap、JavaScript 依赖、更新频率与抓取风险，才能决定采集策略。

5. **评分在赛事层完成。**  
   一个平台可能同时存在 S 级和 R 级赛事，禁止用网站等级批量替代单场赛事评级。

## 下一轮核验任务

  - API / RSS / Sitemap
  - 是否必须登录
  - 是否依赖客户端渲染
  - robots.txt 与服务条款
  - 更新频率
  - 可提取字段
  - 最近一次发现新赛事的日期
- 对中国高等教育学会目录中的赛事建立官方官网映射
- 对国际平台建立主办方回溯规则
- 建立明显收费型、证书型、保奖型赛事的风险词表
